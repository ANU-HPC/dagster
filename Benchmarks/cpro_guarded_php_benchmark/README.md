# `c_pro` indirect guarded-pigeonhole benchmark

This benchmark demonstrates useful parallel SAT search from a two-node DAG generated by `c_pro`. It produces ordinary stand-alone DIMACS CNF instances and compares:

- the two-node DAG generated by `c_pro`; and
- the one-node trivial DAG generated by `c_pro`.

Both arms use the same processed CNF, giving a controlled comparison between structured decomposition and conventional unsplit SAT search.

## Benchmark design

The benchmark uses an indirect guarded pigeonhole construction.

The first `w` variables are selector variables. For each of the `2^w` selector assignments, a decoder determines one activation variable. Each activation variable guards a private pigeonhole problem `PHP(h+1,h)`.

Exactly one activation variable is true under each selector assignment. Every selector assignment therefore activates one UNSAT pigeonhole core, making the complete stand-alone CNF UNSAT.

The hard pigeonhole clauses contain activation variables, not selector variables. Consequently, `c_pro` places only the selector-copy and decoder clauses in node 0, while the hard clauses remain in the terminal node.

Equality-copy clauses increase the interaction-graph degrees of the selector variables. For the width-2 instances, `c_pro` selects variables 1 and 2 for the DAG edge.

The expected DAG structure is:

```text
DAG-FILE
NODES:2
GRAPH:
0->1:1,2
CLAUSES:
0:<proper subset of clauses>
1:0-<last clause>
REPORTING:
1-<last variable>
```

Node 0 must not own the complete formula.

## Files

### Software

- `generate_guarded_php_v2.py` generates the indirect benchmark.
- `check_instance.py` checks a generated CNF against its JSON sidecar.
- `generate_guarded_php.py` is the original direct-guard generator. It is retained as a documented negative design and should not be used for performance experiments.

### Canonical instances

- `gphp_v2_w2_h7`: fast correctness smoke test using four `PHP(8,7)` branches.
- `gphp_v2_w2_h9`: local calibration case using four `PHP(10,9)` branches.

Each canonical case includes:

- `.original.cnf`: output of the Python generator;
- `.original.cnf.json`: generation parameters and SHA-256;
- `.cnf`: formula emitted by `c_pro` after preprocessing;
- `.dag`: two-node `c_pro` DAG; and
- `_.dag`: one-node control DAG.

The generated formulas are ordinary stand-alone DIMACS SAT instances.

## Required `c_pro` interface

This benchmark uses the configurable-width `c_pro` interface:

```text
c_pro [input.cnf [split-width [output-prefix]]]
```

If width and prefix are omitted, the historical defaults remain:

```text
split width = 32
output prefix = x
```

For the canonical benchmark, use split width 2.

## Build

Build in the environment where the experiment will run:

```bash
make -C c_pro clean
make -C c_pro -j 4

make -C dagster clean
make -C dagster -j 4
```

Do not copy locally built binaries between systems with different glibc or `libstdc++` versions. Build independently on the laptop host, inside Docker, and on Gadi.

## Generate and check the smoke instance

From this benchmark directory:

```bash
python3 generate_guarded_php_v2.py \
    --width 2 \
    --holes 7 \
    --boosters 80 \
    --output instances/gphp_v2_w2_h7.original.cnf

python3 check_instance.py \
    instances/gphp_v2_w2_h7.original.cnf
```

Enter the instance directory before running `c_pro`. This ensures that both DAG files are written to the same directory:

```bash
cd instances

../../../c_pro/c_pro \
    gphp_v2_w2_h7.original.cnf \
    2 \
    gphp_v2_w2_h7
```

Check the decomposition:

```bash
grep -- '->' gphp_v2_w2_h7.dag
grep '^0:' gphp_v2_w2_h7.dag
grep '^1:' gphp_v2_w2_h7.dag
```

The edge must be:

```text
0->1:1,2
```

Node 0 must contain a proper subset of the clauses. Node 1 must own the complete clause range.

## Dagster enumeration modes

In the AFSAT branch:

- `-e 0`: terminate when a terminal-node solution is found;
- `-e 1`: exhaust all satisfying assignments through the DAG;
- `-e 2`: find one solution for each disjoint DAG subgraph; and
- `-e 3`: process only one solution for each DAG-node message.

Use `-e 0` for the conventional SAT-decision benchmark. Mode `-e 1` can be used as an exhaustive cross-check. Do not use `-e 3`, because node 0 must enumerate all selector assignments.

Because the canonical instances are UNSAT, `-e 0` cannot terminate early on a terminal solution and must exhaust all generated work.

## MPI process counts

MPI rank 0 is the Dagster master. Remaining ranks are solving workers:

- `mpirun -n 2`: one master and one worker;
- `mpirun -n 4`: one master and three workers;
- `mpirun -n 9`: one master and eight workers.

Use `--oversubscribe` only for Docker correctness and calibration testing. Do not use oversubscribed results as final HPC performance evidence.

## Local experiment

From `instances`:

```bash
TIMEFORMAT=$'real %3R\nuser %3U\nsys %3S'
RESULTS=../results/local
mkdir -p "$RESULTS"

run_instance () {
    NAME=$1
    RANKS=$2
    DAG=$3
    CNF=$4
    ENUM=$5

    {
        time mpirun --oversubscribe -n "$RANKS" \
            ../../../dagster/dagster \
            -m 4 -e "$ENUM" \
            "$DAG" \
            "$CNF" \
            > "$RESULTS/$NAME.log"
    } 2> "$RESULTS/$NAME.time"

    RC=$?
    printf 'exit=%s\n' "$RC" > "$RESULTS/$NAME.exit"
    printf '%-26s exit=%s ' "$NAME" "$RC"
    grep '^real ' "$RESULTS/$NAME.time"
}
```

Run the four principal arms:

```bash
run_instance decomposed_n2 2 gphp_v2_w2_h9.dag gphp_v2_w2_h9.cnf 0
run_instance decomposed_n4 4 gphp_v2_w2_h9.dag gphp_v2_w2_h9.cnf 0
run_instance trivial_n2 2 _gphp_v2_w2_h9.dag gphp_v2_w2_h9.cnf 0
run_instance trivial_n4 4 _gphp_v2_w2_h9.dag gphp_v2_w2_h9.cnf 0
```

Principal comparisons:

- `decomposed_n2 / decomposed_n4`: parallel scaling;
- `trivial_n2 / decomposed_n4`: end-to-end improvement over the serial trivial-DAG reference;
- `trivial_n4 / decomposed_n4`: same-rank decomposition advantage.

## Local calibration result

The width-2, holes-9 instance was run five times for each arm inside the Dagster Docker environment.

| DAG | MPI ranks | Solving workers | Median wall time |
|---|---:|---:|---:|
| `c_pro` decomposition | 2 | 1 | 8.638 s |
| `c_pro` decomposition | 4 | 3 | 6.070 s |
| trivial one-node DAG | 2 | 1 | 9.719 s |
| trivial one-node DAG | 4 | 3 | 12.373 s |

Median results:

- decomposed parallel speedup: `8.638 / 6.070 = 1.423x`;
- end-to-end speedup over the serial trivial DAG: `9.719 / 6.070 = 1.601x`;
- end-to-end wall-time reduction: 37.5%;
- same-rank decomposition advantage: `12.373 / 6.070 = 2.038x`;
- one-worker decomposition advantage: `9.719 / 8.638 = 1.125x`.

All 20 repeated runs exited with status 0.

These Docker measurements are local calibration evidence, not the final Gadi performance result. Final reporting should use non-oversubscribed Gadi runs, multiple repetitions, medians, and captured node and software provenance.

## Scaling controls

- `--width`: selector count and at most `2^width` branches;
- `--holes`: difficulty of each activated pigeonhole proof;
- `--boosters`: equality-copy variables used to keep selectors highest-ranked by `c_pro`.

For four-worker calibration, keep `--width 2` and increase `--holes`. This raises per-branch solving cost without increasing fan-out.

For larger Gadi runs, increase width only after measuring master load and terminal-job duration. Avoid generating millions of very short messages.

## Acceptance checks

Before timing a generated instance, require:

1. the generator checker passes;
2. `c_pro` selects the intended selector variables;
3. node 0 owns a proper subset of the clauses;
4. node 1 owns the complete formula;
5. decomposed and trivial DAG runs terminate normally;
6. `-e 0` and an `-e 1` cross-check agree operationally;
7. the instance is independently confirmed UNSAT with Kissat or another stand-alone SAT solver; and
8. the one-worker runtime is long enough to amortise MPI startup.

For a local four-core result, target at least 20 to 60 seconds in the one-worker reference. Shorter instances are smoke or calibration tests.

## Known failure mode: direct guarding

The original v1 generator placed selector literals directly in every guarded PHP clause. `c_pro` then assigned every clause to node 0:

```text
0:0-<last clause>
```

Node 0 was the complete UNSAT formula and produced no downstream work. V2 fixes this by using activation variables between the selectors and hard PHP clauses. V1 must not be used for scaling measurements.

## Gadi use

Build `c_pro` and Dagster on Gadi using the same AFSAT branch and the Gadi compiler and OpenMPI environment. Do not copy the Docker or laptop executable.

Retain:

- Git commit and branch;
- compiler and OpenMPI versions;
- CNF and DAG SHA-256 values;
- PBS job identifiers and resource requests;
- rank and solving-worker counts;
- wall time, CPU time and peak memory;
- Dagster message and worker-idle statistics, where available;
- all exit statuses; and
- independent UNSAT validation.

The local `h7` case is appropriate for a Gadi smoke test. The `h9` case is a calibration case. Choose larger holes or selector widths only after initial Gadi measurements establish useful terminal-job duration.
